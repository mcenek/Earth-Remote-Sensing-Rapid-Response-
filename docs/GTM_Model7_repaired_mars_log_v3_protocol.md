# Model 7 MARS log-radiometry comparison v3

This failure protocol precedes the versioned v3 trainer. The sealed `mars_clear_data` arrays and the completed baseline MARS trainer, predictions and receipt remain unchanged. This is one targeted preprocessing comparison, not a new cohort or a new architecture. TRAIN-only source inspection found that a local log(B12/B11) target-reference contrast had the expected direction in 95 of 97 positive TRAIN scenes; this is motivation, not proof that it identifies methane. The baseline DEV visual review found missed plumes and field/water/seasonal-change false alarms. The v3 comparison must use the same workload and DEV metrics before any attribution to radiometry.

## Failure cases and end-to-end checks fixed before implementation

1. Reject a missing or changed MARS clear manifest, malformed 100-pixel input or 200-pixel native target/support, duplicate or leaking TRAIN/DEV metadata, changed TRAIN/DEV array/source hash, nonfinite or negative supported digital numbers, or a populated v3 output. Inspect final-test metadata only. Never open final-test arrays, labels or predictions during training, selection or replay.
2. Apply `log1p` to supported raw MARS digital numbers on both current and reference dates, then fit each band's center and scale from supported TRAIN pixels only. Reuse the baseline standardization, clipping and unsupported-pixel handling after that transform. Save the normalizer, manifest, protocol, source file path/hash and exact draw schedule in metadata. Do not mix MARS L1C with CM L2A.
3. Preserve the baseline seed, site-balanced positive/negative crop schedule, D4 augmentation, 48-pixel crop, batch 8, stable residual and Siamese architectures, float32 CPU, AdamW 0.0005 and weight decay 0.0001, gradient cap 1, masked positive-weight-2 BCE plus 0.1 positive-crop Dice, threshold 0.5, 2400 steps, and 600/1200/1800/2400 milestones. Any schedule or objective drift invalidates the one-variable comparison.
4. Before a long fit, each model must pass the unchanged four-real-TRAIN-crop 500-step ordinary-BCE control: positive recall at least 0.8, negative false-positive area at most 0.05, at least 30% loss reduction and nonzero parameter change. Save the fixed crops, pre/post probabilities and checkpoints. Stop if either fails.
5. At each milestone, save full TRAIN and DEV 20 m/native probabilities, support, confusion, positive recall/IoU and negative false-positive area. Use the unchanged DEV Pareto selection rule, including recall at least 0.3 and negative FPR at most 0.05 for qualification. Report no qualified checkpoint if none meets it. Never tune from final-test results.
6. In a fresh process, rehash source, protocol, manifest, checkpoints and probability arrays; recompute the schedule and TRAIN normalizer; replay probe and every retained Pareto checkpoint on full TRAIN/DEV; verify native factor two and exact confusion; write a repeatable E2E receipt. Root must inspect DEV images before any separately authorized final-test inference.
