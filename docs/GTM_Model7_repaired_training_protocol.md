# Model 7 repaired-cohort training protocol

This protocol precedes implementation. It applies only to a newly sealed real Sentinel-2 temporal cohort. The October 23 training, test and confirmation evidence is exposed and cannot select this run's model, threshold, loss, step budget or checkpoint. The repaired cohort must use the existing `GTM_Model7_temporal_cohort_v1` array contract: target/reference `(100,100,6)` in B02, B03, B04, B08, B11, B12 order, 20 m target/support and 10 m native target/support. A geographic component, exact site, acquisition or source asset must not cross train, development and test.

## Failure modes and end-to-end checks fixed before code

1. Reject a missing/wrong schema; duplicate scene ID; absent train, positive-development or negative-development class; unsafe array path; changed train/development array or acquisition hash; malformed grid, target, support or native 2×2 consistency; nonfinite supported radiometry; a group, site or acquisition crossing splits. Validate test *metadata* for split separation but do not open test arrays, labels or prior predictions. Reject a populated output directory. Do not start fitting if validation fails.
2. Fit per-band center and scale only from supported TRAIN pixels on both dates. Require finite values, minimum scale `1e-6`, clip standardized values to ±8 and fill unsupported cells with zero. Save the normalizer and its train-pixel count. Both architectures receive the same 12 normalized date channels; the residual internally uses current plus current-minus-reference, and Siamese uses the two dates directly.
3. Fix a deterministic, equal positive/negative crop schedule for both models. Uniformly choose a train physical site within each class, then a scene at that site. Center positives on supported label-positive pixels and negatives on supported pixels. Use 48×48 crops, batch 8 and D4 transformations applied identically to all channels, target and support. Reject empty crop support, nonfinite inputs or a schedule mismatch. Save the schedule hash and sample coordinates.
4. Before long training, require each unchanged architecture to fit the same four real TRAIN crop examples (two positive, two negative from distinct sites where possible) using ordinary masked BCE for 500 repeated updates. Save initial/final probabilities and checkpoints, loss/gradient curves, parameter change, crop IDs, target, support and inputs. Qualification requires at least 80% positive-crop recall, at most 5% negative-crop false-positive area and at least 30% loss reduction at threshold 0.5. If either fails, stop before long training and diagnose on TRAIN only.
5. If both probes pass, reset each model to its seeded initialization. Run AdamW in float32 CPU with deterministic algorithms, learning rate `0.0005`, weight decay `0.0001`, masked BCE positive weight 2 plus 0.1 positive-crop Dice, gradient norm cap 1, fixed threshold 0.5. Train on the same schedule for 2,400 updates. The safety cap is 15 minutes per model; timeout or nonfinite loss/gradient is a failed run, never an early valid checkpoint. Evaluate both on full TRAIN and positive/negative DEV at updates 600, 1200, 1800 and 2400. Save checkpoint and full-scene probabilities at each milestone, plus loss/gradient history. Do not tune or stop early from exposed test evidence.
6. Report native 20 m confusion and IoU/precision/recall separately for DEV positive and DEV negative scenes, pooled DEV IoU, negative false-positive area rate, and per-scene activations. Retain all nondominated milestone checkpoints in DEV positive IoU (maximize) and DEV negative false-positive area (minimize). The primary selection is the highest DEV positive IoU among Pareto checkpoints with positive recall ≥0.3 and negative false-positive area ≤0.05; if none qualifies, report no qualified checkpoint. Ties use lower false-positive area then earlier update. This selection is made independently for each architecture; comparison uses only TRAIN/DEV.
7. A fresh process must verify source, manifest, array and checkpoint hashes; reload each retained checkpoint; reproduce all saved TRAIN and DEV probabilities within `1e-6`; recompute confusion exactly; and verify shape, finiteness, support and `[0,1]` range. Save a repeatable E2E receipt. Test labels and images remain unopened until both configurations and checkpoint selection are frozen. No old scripts or artifacts are modified.

The development split must contain geographic positive and negative examples. Even then, it is a model-selection set, so its scores are not an unbiased estimate of future geographic transfer.

## Two-branch amendment, fixed before sealed manifest access

Two separate repairs are authorized and must be trained, normalized, selected and reported independently. The MARS branch keeps 100×100 model inputs and 200×200 native labels, with factor-two native support. It replaces the reference with a reviewed earlier no-plume acquisition from the same facility, within 60 days, and checks cloud masks on both dates. Its development positives are previously exposed western Permian examples and its geographic final examples were also previously used by the wider project. They are exploratory regression evidence, never a fresh national estimate.

The MethaneS2CM branch has 32×32 model inputs and 32×32 native labels, factor-one native support. It uses the same six spectral indices for both dates, raw float32 DN values, and a TRAIN-fitted `log1p` radiometric transform before per-band standardization. No reference cloud mask/date is supplied, so the trainer must make no claim of reference clarity. The source H5 is a shared container across splits; hash it once and do not treat its path as a cross-split sample leak. Check geographic/sample identities from manifest metadata, and report any unavailable acquisition identity rather than assuming independence. Do not mix L1C and L2A arrays or normalization across branches.

Both models must pass their branch's own four-crop real-data fit control before long fitting. Use crop size `min(48, image side)` so the 32-pixel branch keeps the full tile. Train and development predictions are saved at every milestone for visual review; final-test arrays and labels stay unopened until a separate explicit freeze action. Dynamic-grid E2E replay must check native factor one or two and full-scene train/development probabilities. The same predeclared 2,400-update budget, loss, threshold, Pareto rule and float32 runtime apply to both branches.

## Suspension amendment before retry

The first MethaneS2CM attempt passed both real-crop controls and saved step-600 residual predictions, then the host suspended the process for roughly nine hours. On resume, the 15-minute wall timer failed before step 601. Preserve this failed attempt. For fresh retries, use a 15-minute **process CPU-time** cap per model and probe, excluding machine sleep and idle. The fixed update count, models, seeds, objective, milestones and decision rule do not change. Retries use a new output directory and repeat both probes from initialization.
