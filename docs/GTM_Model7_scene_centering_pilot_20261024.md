# Bounded scene-centering pilot

This protocol is written before this pilot is implemented or fitted. It follows the TRAIN-only contrast audit in `outputs/GTM_Model7_pipeline_fix_20261024/radiometry_contrast_diagnostic.json`. That audit found pooled methane-like temporal spectral ranking AUC of 0.6382 before and 0.7478 after removal of each scene's median offset. Within-scene ranking cannot change under centering. This is evidence for a preprocessing hypothesis, not evidence of improved model accuracy or proof of methane attribution.

Failure cases: centering with labels or held-out aggregate statistics; making training and inference use different spatial support; deleting difficult scenes; changing the sampler, architecture or loss at the same time; selecting on the consumed external cohort; claiming independent validation from repeatedly exposed DEV; overwriting existing frozen trainers; an inference wrapper silently using the old preprocessing.

Run exactly one new arm, `balanced_full_scene_centered`, against the predeclared `balanced_full_scene` control. Use the identical 38,400 scene/class/domain/D4 draw sequence, original seed, two existing architectures, optimizer, loss, milestones and 4,800-update cap. Use full 100x100 scenes throughout. Preserve 9,600 US positive and 9,600 auxiliary positive draws. Use the same deterministic float32 RTX 5070 settings and CPU checkpoint evaluation/replay. Do not add architecture channels or alter labels.

For each date and band, compute log1p(DN) over that scene's common valid support, subtract that date/band's median, and then standardize. Fit the six global centers/scales only from the centered TRAIN-date pixels. At inference compute scene medians from image pixels and support only, never labels or other scenes. Invalid values remain zero and standardized values are clipped at eight. The image operation is therefore transductive within one input scene but does not fit statistics on the evaluation cohort. It removes absolute scene brightness; loss of useful absolute context is a disclosed tradeoff.

Freeze a separate versioned trainer and all reused code hashes. Verify the preprocessing independently from raw arrays, exact balanced schedule preservation, absence of TEST array access, checkpoint normalization identities, finite score support, fresh CPU replay and native confusion counts. Keep original source arrays unchanged.

Use the existing fixed DEV cutoff grid and precision/recall/false-alarm gate. Compare all 86 exposed DEV scenes, with actual masks and errors for all six plume cases and no-plume failures. Select the new arm only if it improves DEV pooled IoU while passing the existing gate for that model; otherwise retain the full-scene control as the corrected pipeline and show the centering pilot as failed diagnostic evidence. This is model development, not a new independent validation result. Freeze the choices before the consumed 55-case external regression is opened. Do not tune again using that regression, and leave the original sealed TEST untouched.

Stop after this pilot. A failure requires a separately designed geographic validation and additional diagnosis, not an unbounded search on the six DEV plumes.
