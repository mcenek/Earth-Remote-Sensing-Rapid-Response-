# Model 7 balanced-loss CM recovery v2

This protocol precedes the versioned v2 trainer. The baseline source and output remain unchanged. The baseline MethaneS2CM train schedule has 19,200 real draws and 6.751% supported plume pixels, with 13.502% plume pixels inside positive-scene draws. At baseline residual steps 600 and 1200, full TRAIN recall is only 0.615% and 2.459%. These train-only measurements justify testing a class-balanced objective. The baseline full runs and fresh-process E2E must finish first.

Use the repaired MethaneS2CM 32×32 L2A branch only, preferably the separately sealed strict reference-quality repair if it arrives before this run. Do not rewrite or combine its data with MARS L1C. The choice of reference variant must be recorded before training. If v2 uses a different reference variant from baseline, the result changes both data and loss; report this as a combined comparison, not an isolated causal loss ablation.

## Failure cases and E2E checks fixed before code

1. Preserve the baseline trainer, protocol, arrays, checkpoints, receipts and predictions byte-for-byte. Reject a populated v2 output. Validate the selected new manifest, all TRAIN/DEV array/source hashes and group/site separation, positive and negative DEV classes, and native 32-pixel label/support consistency. Do not open final-test arrays or labels.
2. Fit `log1p` plus per-band center/scale only on supported TRAIN pixels from both dates. Save the new manifest identity, v2 trainer path/hash, normalizer, exact 38,400-draw schedule and hash. Use the same site-balanced positive/negative crop schedule, D4 transforms, seed, 32×32 crop, batch 8, unchanged GroupNorm residual and Siamese architectures, Torch 2.11 float32 CPU, AdamW learning rate 0.0005, weight decay 0.0001, norm cap 1 and threshold 0.5.
3. Both models must first pass the unchanged four-real-TRAIN-crop ordinary BCE fit control: 500 identical updates, positive recall at least 0.8, negative false-positive area at most 0.05, at least 30% loss reduction and nonzero parameter change. Stop before long training if either fails. Save before/after probabilities, inputs, targets, support, checkpoints and curves.
4. For full training only, compute masked positive-pixel BCE mean and masked negative-pixel BCE mean separately, then average those two means equally. If a batch has no supported pixels of one class, use the sole present class mean with no division by zero; reject a batch with no support. Add the unchanged 0.1 positive-crop Dice term. Reject nonfinite loss, gradient and probability. This changes the baseline loss only; no explicit positive weight is applied to BCE.
5. Reset both models to the same seeded initialization and run 4,800 fixed updates. Evaluate full TRAIN and positive/negative DEV at updates 1200, 2400, 3600 and 4800. Save checkpoints, curves, 20 m/native confusion, and every TRAIN/DEV scene probability at each milestone. A 30-minute process CPU-time cap per model protects compute while excluding machine suspension. Timeout is a failed run.
6. Retain DEV Pareto checkpoints in positive IoU versus negative false-positive area. The unchanged primary rule chooses highest DEV positive IoU among Pareto checkpoints with positive recall at least 0.3 and negative false-positive area at most 0.05, with lower FPR and earlier update as ties. If none qualifies, report no qualified checkpoint. No test, prior confirmation, or final-holdout score may change the rule, threshold or checkpoint.
7. A fresh process must rehash source, protocol, manifest and saved arrays; recompute schedule; reload each retained checkpoint; replay full TRAIN/DEV 32×32/native probabilities within `1e-6`; verify support and exact confusion; and save an E2E receipt. Root reviews DEV prediction images before a separately authorized final-test inference.
