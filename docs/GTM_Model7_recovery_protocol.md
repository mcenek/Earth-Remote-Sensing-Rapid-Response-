# Model 7 controlled training recovery, fixed before execution

The October 23 residual and Siamese test results are exposed. They are historical evidence only. This recovery uses the frozen cohort's train labels and negative-only development labels. No old test label, old test prediction, or old test score may enter a training, threshold, budget, loss, or checkpoint decision. The original trainer, source snapshots, model weights, receipts, and viewer experiments remain byte-for-byte unchanged.

## Failure cases and end-to-end checks, written before recovery code

1. Reject a manifest, array, or acquisition source whose hash, shape, split, group, support, or label contract fails the frozen validator. Do not start a run after validation fails. Test arrays may be read only through the original `labels=False` path during validation; recovery never opens test label keys.
2. Reject output directories that already contain data. Save the manifest hash, original trainer hash, recovery source hash, schedule hash, full configuration, normalization, initial and final checkpoints, loss curves, and train/development metrics. Stop on nonfinite loss, nonfinite gradients, or an exceeded time cap.
3. First prove a fixed pair of positive and negative train crops can be fit by each unchanged architecture with ordinary masked BCE and positive weight 1. Record identical probe crop IDs, coordinates, augmentation, initial/final loss, nonzero parameter change, and positive recall and negative false-positive rate at threshold 0.5. If this fails, do not claim class weighting or update budget is the cause.
4. Run a residual 2×2 ablation on the same seeded schedule: positive weight 1 or 10 crossed with 360 or 1800 updates. All other loss terms, architecture, normalization, optimizer settings, and threshold remain the original values. The long run's 360-update checkpoint is the short arm, so the exact first 360 optimizer steps are identical. Compute full-scene train confusion, train positive recall and IoU, and negative-development false-positive area at both checkpoints. Save every train-scene probability map for the selected final checkpoints.
5. Choose weight and update count from train discrimination and negative-development false activation only. State the choice rule and numbers in the receipt. Then run Siamese with precisely the selected objective and update count on the same schedule. A zero-positive-recall all-negative model cannot count as a recovered detector regardless of its development false-positive rate.
6. A fresh process must reload each final checkpoint and reproduce saved train probabilities to tolerance `1e-6`; verify shape, range, finiteness, support, hash, train confusion, and development confusion. Verify the original trainer SHA-256 still matches the recovery receipt. The E2E JSON receipt is the repeatable artifact.

The selected model configuration is frozen before any new held-out evaluation. Development contains only negatives, so it cannot measure positive generalization. This experiment can diagnose optimizer learnability and training behavior; it cannot establish a usable detector on independent positives.
